# Submission Workflow Agent Improvement Plan

## Objective
Develop a robust submission workflow agent capable of handling 100k+ submissions with 100% accuracy, and implementing interaction protocols for "stuck" scenarios.

## Proposed Strategy

### 1. Tiered Submission Engine
- **Tier 1: Direct API (Fast Path)**
    - Leverage existing `fast_submitter.js` for supported ATS (Greenhouse, Lever, Ashby).
    - If API submission fails, automatically transition to Tier 2.
- **Tier 2: Browser Automation (Robust Path)**
    - Use `browser_submitter.js` as a fallback.
    - Enhance with "stuck" detection.

### 2. "Stuck" Scenario Detection & Protocols
- **Detection Mechanisms:**
    - Monitor for navigation timeouts (waiting for a page load that exceeds a threshold).
    - Monitor for presence of known error elements or validation messages on the page.
    - Track time spent on each step and flag if it exceeds expected norms.
- **Protocol:**
    - **Self-Healing:** If "stuck", attempt a retry or a page reload (with exponential backoff).
    - **Escalation:** If repeated retries fail, mark the application as "stuck" in a database/queue and move on to the next application, so progress is not halted.
    - **Help Request:** Log full page state (screenshot, DOM snapshot, console logs) for asynchronous analysis and "stuck" resolution (e.g., TSenta integration).

### 3. Implementation Plan
- **Modify `browser_submitter.js`**:
    - Introduce a `SubmissionContext` class to track the state, elapsed time, and errors for the current application.
    - Wrap key steps (page navigation, filling forms, submitting) with timeout and error handling.
    - Add a function to capture state upon failure/stuck detection.
- **Integrate into Workflow**:
    - Update the main submission runner (likely in `service/auto_apply_engine.go` or `cmd/auto_apply_runner/main.go`) to use the new tiered approach.

## Next Steps
1.  Implement `SubmissionContext` and basic error/stuck detection in `browser_submitter.js`.
2.  Update the `fill...` functions in `browser_submitter.js` to report status to the `SubmissionContext`.
3.  Add logging/reporting for stuck applications.
